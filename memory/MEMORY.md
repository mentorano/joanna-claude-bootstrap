- [Persona doctrine](feedback_persona_doctrine.md) — Persona-friendly defaults, affordance restraint, terminology canon, mock-the-breadth. The tiebreaker for any UX micro-decision. Project supplies specific persona name and terminology.
- [Workflow](feedback_workflow.md) — Driver mode (chunk granularity), documentation reflex, chunk-end persona+reflection passes, verify scope against code not stale docs.
- [Iteration killers](feedback_iteration_killers.md) — When already in iteration loop: ask for console+network, prototype UX variants, ask strategic question, stop half-baked compromises. Companion to pre-implement-gates.
- [Tooling](feedback_tooling.md) — Edit not sed, git -C not cd, venv binary not source, pytest/curl not python -c, visible Chrome not headless. Extended rationale; hard rules in project root CLAUDE.md.
- [Audit default](feedback_audit_default.md) — Value statement: anything forensically meaningful gets persisted. Audit-every-mutation is strictest application.
- [shadcn *Label primitives require Group ancestor](feedback_shadcn_grouplabel.md) — DropdownMenuLabel + analogous wrap Base UI GroupLabel; runtime crash without Group wrapper. Library gotcha.
- [Base UI Select.Value lazy fallback](feedback_baseui_select_value.md) — SelectValue shows raw value (not label) until SelectContent mounts. Use children-as-function. Library gotcha.
- [Base UI render prop (not asChild)](feedback_baseui_render_prop.md) — shadcn v4 uses Base UI; element substitution is `render={<X/>}`, not Radix `asChild`. For styled Link: use `buttonVariants` className. Library gotcha.
- [Smoke + downstream display effects](feedback_smoke_test_downstream.md) — Mutation smoke must walk every surface that reads affected data, not just the mutation flow. Soft-delete: always test existing references. Companion to workflow chunk-end persona pass.
- [Permission symmetric admin for shared resources](feedback_permission_symmetric_admin.md) — Admin page for resource X where lower role already mutates via another flow: default to lower-role+ view+edit; restrict only destructive ops to admin.
- [Cross-impact reasoning](feedback_cross_impact_reasoning.md) — When changing a constraint/validator/lifecycle transition, enumerate ALL related paths (create/update/hide/unhide/archive/restore) in SAME chunk. Bugs from forgotten cross-impact cost more than the original change.
- [User-visible errors](feedback_user_visible_errors.md) — Every async user-triggered mutation needs explicit try/catch + toast/UI feedback. Never silent fail to console. Use `extractFriendlyError(err)` helper to surface Pydantic 422 / domain detail strings.
- [Cache invalidation cascade](feedback_cache_invalidation_cascade.md) — When mutation changes X, invalidate ALL queryKeys returning X-derived data — including embedded copies in other resources' responses, denormalized lifted tables, computed summaries.
- [Theme-aware visual feedback](feedback_theme_aware_visual_feedback.md) — Visual cues must be tested against actual theme palette. „from-card to-transparent" is invisible on card-bg. Use inset shadow / theme-independent recipes.
- [Consistent save model](feedback_consistent_save_model.md) — Don't mix batched + per-action save in same surface. User settles into one model; mixed causes silent data loss.
- [UI state hygiene](feedback_ui_state_hygiene.md) — Auto-close after natural completion; wrap around serial nav; progressive disclosure for unhelpful affordances. Don't leave user in implicit states.
- [Confirm dialog for impactful saves](feedback_confirm_dialog_rule.md) — Every impactful/destructive save in admin/config surfaces goes through ConfirmDialog with before→after preview. Promise-based `useConfirm()` hook pattern.
- [Retro: rank by impact](feedback_retro_rank_by_impact.md) — When analyzing a session for RL items, lead with principle-level rules (promote to CLAUDE.md + bootstrap), not flat chronological list. User shouldn't have to pull principles out.
- [Memory birth → audit sweep](feedback_memory_birth_audit.md) — When you formalize a memory rule that names a bug class, IMMEDIATELY grep codebase for other instances of the same pattern. Don't wait for next bug. Memory without audit = N-1 instances still in code.
- [Prototype before deep build](feedback_prototype_before_deep_build.md) — For UX decisions where the right pattern is uncertain (save model, mode granularity, confirmation cadence), wire ONE control with the candidate pattern → validate → only then replicate across surface. Avoids sunk-cost refactors when wrong pattern picked.
