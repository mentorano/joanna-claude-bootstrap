- [Driver mode — chunk-granularity execution + persona exhaustion pass](feedback_driver_mode.md) — Execute whole chunks; ask only for destructive actions, real product forks, or blockers. Treat scope as direction; at chunk end run persona-usage exhaustion pass before declaring done.
- [Documentation reflex](feedback_doc_reflex.md) — Proactively capture stances/decisions/gotchas as they emerge; decision tree for where each kind goes; chunk-end checkpoint.
- [Default to persistence — audit and DB-worthy state](feedback_audit_default.md) — Anything forensically meaningful gets persisted, not ephemeral. Audit-every-mutation + override/context metadata + failed-mutation logging.
- [Browser smoke tests — prefer visible Chrome](feedback_browser_smoke.md) — Default to visible Chrome via MCP for chunk-end smoke; headless agent-browser only when owner isn't watching.
- [Backend smoke pattern — pytest or curl, not `python -c`](feedback_backend_smoke_pattern.md) — Use pytest tests or curl-to-API for backend smoke; avoid `cd && source venv && python -c` heredoc.
- [Prefer native tools over shell escapes](feedback_prefer_native_tools.md) — Edit not `sed -i`, `git -C` not `cd && git`, venv binary not `source activate`, Grep/Glob not shell pipes.
- [Persona-friendly defaults](feedback_persona_defaults.md) — When choosing a UX default, pick the more-visible / lower-effort option. Don't make them hover, keyboard, or click-to-reveal basic things.
- [Mock the breadth, deliver the depth](feedback_mock_breadth.md) — When multi-X feature, render all X-en in UI early (with real names); functional depth follows. Yields better design conversations.
- [Native HTML affordances — don't duplicate](feedback_native_affordances.md) — Before adding custom UI next to a native input, check what the browser already provides. `<input type="search">` has own ×; hide it via CSS pseudo-element if you add own.
- [Extend by matching existing, not by restructuring](feedback_extend_match_existing.md) — When adding new functionality в съществуваща system, нee live-ва максимално аналогично на старото (layout, sections, features). Адаптирай новото към старото, не обратното. Conflict → ask, не разрешавай еднолично. **Pre-implement checkpoint applies to ANY new UI feature** (extension OR feels-greenfield) — inventory pilot's features OR foundation primitives first.
- [Proactive layout-shift checks at every UI implement](feedback_no_layout_shift_proactive.md) — Преди render path, mental checklist: read↔edit / show-hide / loading→loaded / empty→filled / toggle / append. „Не подскачай UI-я" е active checkpoint, не post-hoc fix.
- [Prototype UX variants before implement](feedback_prototype_ux_variants.md) — При UX choice point с >1 defensible option, build working prototypes на всички (switchable), не just text-описание. Owner избира на реалното UI behavior.
- [Portalled content needs explicit event containment](feedback_portal_event_containment.md) — React events bubble през React tree, не DOM tree. createPortal-ed overlays propagate to parent React component → row-click конфликтя с popover buttons. Single stopPropagation на boundary е DRY.
- [Overlay (absolute) — preferred default за anchored UI](feedback_overlay_vs_floating.md) — position:absolute в relative parent scroll-ва с anchor. position:fixed (floating) detach-ва при scroll. Fixed е escape hatch за clipped containers (изисква scroll listener).
- [Simulate end-to-end преди declare-done](feedback_simulate_e2e_before_done.md) — За UX changes mental-симулирай state transitions / click flows / parent-child events / conditional renders. 5 min pre-flight saves 30 min iteration loop.
- [Affordance restraint — less is more](feedback_affordance_restraint.md) — Не добавяй nav links / helper buttons „just in case". Persona test: real use case + redundancy check + noise cost + would user actually click it?
- [Без half-baked визуални решения](feedback_no_half_baked_visuals.md) — Left-aligned без mx-auto, fixed min-h с visible празно пространство, overflow-x scroll с hidden content — да не. Or clean full solution, or ask owner preference.
- [Shared components не hardcode-ват reference data ids](feedback_no_hardcoded_pilot_id.md) — FilterPanel/AuditFilter/etc. accept registerType/scope като prop, conditional render на schema. Hardcoded „PILOT_ID = 1" в shared component е extend-by-matching violation.
- [Chunk-end reflection protocol](feedback_chunk_end_reflection_protocol.md) — Explicit reflection pass след persona pass: analyze catches/iterations/recurring patterns, categorize project-specific vs cross-project, route към project CLAUDE.md + memory + bootstrap memory/overlay. Bootstrap audit hook = safety net reminder, не auto-trigger.
- [Native title= is too slow for primary discovery](feedback_native_title_too_slow.md) — Native HTML `title=` has 1-2s delay; for affordances users need to discover via hover (abbreviated headers, icon buttons), build a CSS-only tooltip with opacity transition. Keep `title=` set as a11y fallback.
- [Verify scope against code, not stale docs](feedback_verify_scope_against_code.md) — Before estimating chunk scope or making framing-laden recommendations from STATUS/ROADMAP/handoff, read the actual code. Owner pushes „check it" → accept immediately, don't double down on doc-derived framing.
- [Visual baseline at V1](feedback_visual_baseline_v1.md) — UI features V1 must include: mixed card sizes + icons + design tokens + chart palette overrides + hierarchy. Functional-but-flat V1 triggers predictable „looks dry / ugly" feedback and forces visual iteration.
- [Persona value PRE-build (analytics)](feedback_persona_value_pre_build.md) — За analytics/dashboards/reporting features: brainstorm „what does the boss / operator want to see" BEFORE picking cards. Schema-down мышление for behavioral features е anti-pattern. Persona value list драйв-ва queries, not the reverse.
- [One pattern per interaction, declared upfront](feedback_pattern_declared_upfront.md) — Feature with similar controls (period selector, scope selector, filter) → declare ONE pattern upfront („Tabs everywhere") преди да build first component. Не pick per-card. Inconsistent mix triggers predictable UX feedback.
- [Cache invalidation audit on new query](feedback_cache_invalidation_audit.md) — Every new TanStack queryKey → audit existing mutations → add invalidateQueries in onSuccess. Без този checkpoint, нови queries silently stale след mutations. Common React Query pitfall.
- [Strategic questions early](feedback_strategic_questions_early.md) — When feature has >1 defensible architectural path (layout, scope, IA) → ask owner choice BEFORE deep imp. Pivots in middle of implementation (revert + redo) are expensive. „Which path?" is cheaper than „revert and try other approach".
